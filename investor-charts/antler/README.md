# ShotCount Antler investor charts

## Recommended order

### 1. Cheap intelligence. Deterministic reliability.

Subtitle: *Frontier reasoning only when necessary.*

- **Takeaway:** ShotCount uses Luna by default, handles infrastructure deterministically, and reserves Sol for verified reasoning repair.
- **Metrics:** 3/3 targeted failure classes passed; 100% execution precision; zero manual rescues, duplicate/unintended actions, and infrastructure-triggered Sol calls.
- **Limitation:** The single Sol exercise was deliberate and does not measure production escalation frequency.
- **Placement:** Main deck — architecture/technical credibility.

### 2. Agentic execution costs cents per active user

- **Takeaway:** At 20 successful agentic tasks per month, measured model inference is about $0.17 per active user.
- **Metrics:** $0.0084093269 per successful task; 5/10/20/50/100 tasks cost $0.04/$0.08/$0.17/$0.42/$0.84.
- **Limitation:** Model inference only; excludes all other infrastructure.
- **Placement:** Main deck — unit economics.

### 3. ShotCount turns known agent failure modes into recoverable states

- **Takeaway:** The execution layer directly resolves browser timeout, stale provider state, and cross-tool ordering failures.
- **Metrics:** All three targeted production-path acceptances passed with 100% execution precision.
- **Limitation:** Targeted acceptance proves the known mechanisms, not a universal task-success rate.
- **Placement:** Main deck — technical proof.

### 4. The to-do list becomes an execution interface

- **Takeaway:** ShotCount turns persistent tasks into provider-confirmed real-world outcomes and visible accountability.
- **Metrics:** Conceptual product flow; no quantitative claim.
- **Limitation:** The loop is a product model, not measured conversion or retention data.
- **Placement:** Main deck — product thesis.

### 5. Model inference remains small at early scale

- **Takeaway:** At 2,000 active users and 20 successful tasks each, estimated model inference is $336.37/month.
- **Metrics:** Exact scenarios from 5 to 100 tasks/user using $0.0084093269 per successful task.
- **Limitation:** Inference only, not total COGS.
- **Placement:** Appendix — scale economics.

### 6. Measured execution precision

- **Takeaway:** Across the cited measured runs, provider-visible actions were intended and exactly once.
- **Metrics:** 100% execution precision, zero duplicate/unintended actions, zero manual rescues, 3/3 targeted acceptance.
- **Limitation:** Precision is not the same as universal reliability or task success.
- **Placement:** Appendix — safety evidence.

### 7. Sub-cent model economics for real-world execution

- **Takeaway:** Luna already provides viable execution economics before adding any unsupported production escalation claim.
- **Metrics:** Broader benchmark: 90.0% success, 100% precision, 4.80/5 Distance-to-Done, $0.007738/success; conservative production-path unit reference: $0.008409/success.
- **Limitation:** The broader 60-run benchmark and targeted 3/3 acceptance are distinct evaluations and are not directly compared.
- **Placement:** Appendix — measured model economics.

### 8. ShotCount harness ablation — live execution success by category

- **Takeaway:** In a controlled same-model comparison, the ShotCount harness led Cross-tool, tied Calendar, and trailed the minimal baseline in Email and Browser; the result is mixed rather than a claimed aggregate uplift.
- **Metrics:** With harness vs without harness: Email 93.3% vs 100.0%; Calendar 100.0% vs 100.0%; Cross-tool 73.3% vs 66.7%; Browser 73.3% vs 80.0%.
- **Limitation:** 15 live runs per category per condition; provider conditions were sequential and small one-run differences are noisy. Overlapping bars share a zero baseline and are not additive.
- **Placement:** Appendix — controlled harness ablation and technical diligence.

## Main-deck recommendation

Use charts 1–4. Place the 100% precision line inside the architecture slide and keep the standalone precision visual for diligence or appendix discussion.

## Intentionally excluded

- **“Frontier inference is an exception” quantitative stack:** excluded because no measured production Sol-escalation frequency exists. The architecture chart communicates policy without implying a percentage.
- **Sol/Terra/Luna leaderboard:** excluded because it distracts from the production architecture and the request explicitly forbids it.
- **Luna primitive vs pre-acceptance uplift:** excluded because success fell from 90.0% to 86.7%; presenting it as harness uplift would be misleading.
